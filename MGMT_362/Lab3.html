1. R Markdown Basics

R Markdown lets you combine analysis + code + results in one place. Source vs. Visual: in our work, we focus on the Source view rather than the Visual view, and the Visual view is much easier to use than Source.

1.1 Anatomy of an R Markdown file

An .Rmd file has:

  • YAML header (top block between ---)

For example, the Rmarkdown code for this Lab at top,

---
title: "Lab3: Intro to R Markdown and MySQL"
output: html_document
---

  • Markdown text (headings, bullets, math, etc.)

    • Bold: **bold text** → bold text
    • Italic: *italic text* → italic text
    • Title levels: Use #, ##, ###and comes after the text title
    • Bullet point: Use - Space and comes after the Bullet point
    • Adding hyperlinks: Use [Website Name](Website Link) such as [RStudio](https://posit.co/) → RStudio
    • Adding images: Use ![](Website Link) such as ![](https://posit.co/wp-content/uploads/2014/08/the-r-markdown-cheat-sheet.jpg) →

  • Code chunks by using backtick (` is the backtick, which is usually located in the top left corner, directly below the Escape key and above the Tab key, next to the “1” key on the number row.)

For example,

```{​r}
# your R code
```

1.2 Your first chunk

x <- 10
y <- 3
x / y
[1] 3.333333

1.3 Common chunk options

Chunk options control what is shown when you knit.

1.3.1 Show code and output (default)

This is code in Rmarkdown looks like:

```{​r}
mean(c(1, 2, 3, 4, 5))
```

This is output in Rmarkdown after Knit:

mean(c(1, 2, 3, 4, 5))
[1] 3

1.3.2 Hide code, show output (echo=FALSE) after knitted

This is code in Rmarkdown looks like:

::: {.cell}
::: {.cell-output .cell-output-stdout}

```
[1] 55
```


:::
:::

This is output in Rmarkdown after Knit (code is gone, only output):

[1] 55

1.3.3 Show code, hide output (eval=FALSE means do not run)

This is code in Rmarkdown looks like:

::: {.cell}

```{.r .cell-code}
# This will appear as code in the report but will NOT run.
install.packages("DBI")
```
:::

This is output in Rmarkdown after Knit (only show code and didn’t run code):

# This will appear as code in the report but will NOT run.
install.packages("DBI")

1.3.4 Run code but hide everything (include=FALSE)

This is code in Rmarkdown looks like:

```{​r, include=FALSE}
# Useful for setup steps you don't want printed.
z <- rnorm(5)
```

And there are no codes and outputs at all.

2. SQL Basics (Concepts + Examples)

SQL (Structured Query Language) is used to interact with databases.

2.1 Why SQL matters for business analytics

  • Many organizations store data in databases (MySQL, PostgreSQL, SQL Server, etc.)
  • SQL allows you to:
    • filter rows (WHERE)
    • select columns (SELECT)
    • aggregate (GROUP BY)
    • join tables (JOIN)
  • R (or Python) is then used for modeling, visualization, and reporting.

2.2 Core SQL pattern

SELECT columns
FROM table
WHERE conditions
GROUP BY columns
ORDER BY columns;

2.3 Example SQL statements (we already cover this in our DANL 330 class)

-- Select a few columns
SELECT customer_id, region, revenue
FROM customers;

-- Filter rows
SELECT *
FROM orders
WHERE order_total > 100;

-- Aggregation
SELECT region, AVG(revenue) AS avg_revenue
FROM customers
GROUP BY region;

-- Join
SELECT o.order_id, c.region, o.order_total
FROM orders o
JOIN customers c ON o.customer_id = c.customer_id;

4. Running SQL Queries from R

You can send SQL to the database using dbGetQuery().

4.1 SELECT + WHERE

q1 <- "
SELECT customer_id, customer_name, region
FROM customers
WHERE region = 'West';
"

west_customers <- dbGetQuery(con_sqlite, q1)
west_customers
  customer_id customer_name region
1           6    FreshFoods   West
2           7     GreenTech   West

4.2 Aggregation: GROUP BY

q2 <- "
SELECT c.region,
       COUNT(o.order_id) AS num_orders,
       ROUND(AVG(o.order_total), 2) AS avg_order,
       ROUND(SUM(o.order_total), 2) AS total_revenue
FROM orders o
JOIN customers c ON o.customer_id = c.customer_id
GROUP BY c.region
ORDER BY total_revenue DESC;
"

region_summary <- dbGetQuery(con_sqlite, q2)
region_summary
     region num_orders avg_order total_revenue
1      West          9    152.42       1371.80
2     South          5    254.97       1274.83
3   Midwest          4    181.89        727.56
4 Northeast          2    294.14        588.28

4.3 Business interpretation

Based on the table above:

  • Which region has the highest total revenue?
  • Which region has the highest average order?
  • Are those the same region? Why might they differ?

Key Takeaways

  • R Markdown supports reproducible analytics: your code and results live together.

9.2 Total revenue by segment (B2B vs B2C)

q_sr <- "
SELECT c.segment,
       COUNT(o.order_id) AS num_orders,
       ROUND(SUM(o.order_total), 2) AS total_revenue,
       ROUND(AVG(o.order_total), 2) AS avg_order
FROM orders o
JOIN customers c ON o.customer_id = c.customer_id
GROUP BY c.segment
ORDER BY total_revenue DESC;
"

segment_revenue <- dbGetQuery(con_sqlite, q_sr)
segment_revenue
  segment num_orders total_revenue avg_order
1     B2B         14       2146.12    153.29
2     B2C          6        829.07    138.18

Interpretation idea:
- total_revenue shows which segment drives more revenue overall
- avg_order shows which segment tends to place larger orders
